# Unified study workspaces

Release: `study-unified-20261028-1`. This is an interaction/presentation and workflow correction, not a new physical solver or accuracy claim.

## User task

A student moves from Sun Hours to the newer studies to review the same project, inspect evidence and export a design argument. Inconsistent navigation, scrolling, view controls and repeated input entry were adding work. The correction uses the existing Sun Hours workflow as the reference: Settings and Export on the left, model or weather charts in the centre, Results and Charts on the right. Native panel scrolling keeps settings/export on a single page.

## Delivered changes

- Sky Exposure, Shade Benefit, Solar Envelope, local reference-engine preparation and structural frame screening share one viewport controller. Plan is an orthographic top projection; 3D is perspective. Plan + 3D draws both cameras using one renderer/scene and scissored viewports, not duplicated geometry or separate analytical models. Climate and Passive Design use the same shell with appropriate charts instead of an irrelevant building view.
- Actual Sun Hours native navigation is the reference: 3D left drag rotates, middle drag dollies, right drag pans; Plan left/right drag pans and middle drag dollies; wheel zooms in both. Buttons and keyboard F/+/- provide Fit and zoom. The split panes have independent hit areas and camera controls. View changes retain target, direction and zoom intent, adjusting framing for aspect changes; input/result updates do not reset the camera.
- Fit computes actual source/study bounding corners against both orthographic and perspective frusta. Narrow split-view aspect ratios are included. Both cameras frame the actual source instead of relying on a fixed camera-distance multiplier. Source triangles and analytical coordinates are unchanged.
- One event-driven WebGL scene, capped DPR, shared source buffers, no animation clock, and explicit disposal of controls, grid, observers, geometries and materials. There is one canvas per spatial workspace. The 2D numeric interface remains usable if WebGL cannot initialize. Split mode intentionally halves each viewport's width; fit, zoom and independent controls remain available.
- Pointer hover shows actual point values/units. Clicks on sky samples update their mask. Local daylight-factor hover uses uncapped actual DF, not the percentage remapped for color. Preview points do not claim calculated results. Clicking a local source surface focuses its optical-material assignment instead of editing the building.
- Environmental completed, validated results auto-save once by default, with an explicit Auto-save control. Manual save remains available when auto-save is off. Existing source/input/duplicate checks and historical records remain. No analysis starts solely because a view changes.
- Local sensor-region/optical inputs and confirmation state are remembered per unchanged model version and geometry fingerprint. Changed source geometry does not inherit reviewed assumptions silently. Imported result files find their exported task by ID in the selected project/version, removing unnecessary manual task selection. Engine version, sensor and source checks still apply.
- Weather charts occupy the centre and numerical tables the right. Chart text is redrawn for actual pane width and DPR; dark charts use gray rather than white. Input changes, cancellation and failures do not leave stale charts looking like current results. Report exports retain actual charts and numeric tables after reparenting.
- Five new study covers have 1200×900 day/night images generated by the existing catalogue renderer, standard site model, exact standard orthographic camera, title/footnote typography and colors. Study-specific additions are explicitly **illustrative diagrams**, not user results or uncomputed energy/comfort outcomes. No existing cover is repainted. Regenerate with `tools/render-environment-covers.cjs`.

## Verification

`tests/study-unified-ui.cjs` reads the actual Sun Hours mouse mapping, then performs real mouse drags/wheel gestures in each new spatial study. It verifies independent split panes, camera retention, all source/study bounds after Fit, actual point-to-mask interaction, unchanged source models, native three-column bounds at five laptop sizes, input retention, auto-save without a second click, stale-chart invalidation, gray charts and cover/theme loading.

Existing environmental, structural and actual local Radiance acceptance tests cover computation, cancellation, original coordinates/material inputs, history, reports and raw exports. The existing real EnergyPlus integration remains separate and unchanged. CI repeats the workspace checks against the actual published website. Release status must be reported from the completed public checks, not from a local build alone.

Desktop/laptop is the current priority. At narrow widths the same controls stack with explicit scrolling; no separate phone workflow or new scientific capability is claimed. Geometric sky/shade/envelope methods, reference-engine recipe limits and structural screening limits remain those of their recorded calculations.
