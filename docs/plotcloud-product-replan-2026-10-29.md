依据：用户新想法、仓库 AGENTS.md、线上 `/plotcloud/mvp/` 实际页面、多个现有工作树代码，以及 Ladybug Tools 官方文档。下文“应”“建议”“目标”均描述拟建行为；“现有”仅指核对到的能力。

## 1. 执行摘要与假设清单

### 1.1 产品定位与关键判断

**PlotCloud 帮助建筑师在保留现有建模习惯的前提下，用同一套项目条件比较设计方案，并把可追溯的性能证据交付给客户。**

最值得优先交付的成果是：一份说明“改了什么、结果如何变化、依据与局限是什么、下一步怎么改”的 A/B 方案报告。产品进展应按完成这项任务的时间、重复输入次数、返工和交付质量衡量。

采用以下产品骨架：

1. 项目是输入、模板、模型、方案、计算、反馈和报告的容器；首页首先支持创建与继续项目。
2. Simulation 只有三个顶层入口：**建筑分析、室内分析、表格类型**。Workbench 是可选的模型与属性编辑工作区；Rendering 与 Boards 属于交付流程，不成为第四、第五种分析。
3. Simple / Advanced 是项目界面的通用分层；单项覆写在两种模式均可用。模式不决定算法精度，不改变数据。
4. 建立统一的最小输入、推导、校验和来源记录；每个分析只订阅自己需要的输入。
5. “采纳并运行 Plan B”是核心能力：建议必须对应可应用的参数或对象变更，并自动完成相关分析的重跑和 A/B 更新。
6. 先完成一个真实的日光/遮阳改进闭环，再扩展全年光环境、能耗、舒适度、CFD 和街区能力。
7. 保留现有 22 个分析入口的计算与历史资料，通过重分类和适配器迁移；不能把所有浏览器筛查直接改名为 Honeybee 或专业验证。

### 1.2 三项必须纠正的预期

- **地址足以启动气候研究，无法凭空提供真实建筑的室内模型。** 建筑日照需要体量，室内采光需要空间与开窗，能耗需要热区及围护结构，结构需要杆件与受力条件。Simple 自动补充的是合理且明示的假设，不是未知事实。
- **Ladybug 全部核心分析能力是目标能力目录，不是当前已交付状态。** 覆盖核心问题、计算路径和结果，不要求把每个 Grasshopper 数据转换组件做成独立按钮。对尚未接入、需要外部引擎或需要额外信息的项目必须标明状态。
- **表格类型与另外两类的分类维度不同。** 前两者按研究对象分，表格按成果形式分。因此规定每个任务只有一个主入口，同时允许复用其结果；不能为了三分法重复运行同一分析。

## 3. 项目入口、模式与项目级参数化

### 3.1 首页与项目创建

登录后首页显示“新建项目”、最近项目、全部项目与搜索。项目卡显示名称、地址、用途、阶段、最近方案、结果状态、Simple/Advanced、平台推导项数量、用户覆写项数量、存储状态。名称/描述/客户资料可编辑；归档与删除分开。

游客进入介绍首页时，主操作为“创建项目”，并保留“直接使用分析工具”“打开示例”。独立工具运行前可保存为本地研究，完成后加入项目；不要求先建场地、再重画模型。

创建面板：

- 模式：Simple（默认）/ Advanced。
- Simple 首屏仅要求地址或坐标；项目名自动取地址简称，可立即编辑；描述、客户、用途可稍后补齐。已有默认项目模板或用户主动选用途时应用该模板；没有用途时先完成气候研究。
- 点击“创建并准备”后自动获取天气，进入项目概览。概览展示“气候已准备 / 建筑分析待体量 / 室内分析待空间与开窗”，提供“导入模型”“绘制体量”“使用明确标注的示例”。不会把场地周边建筑误当成用户设计。
- Advanced 在同一面板展开 EPW 选站/上传、模型导入、用途/地区/年代模板、单位/上轴/朝向和参数集；可先创建草稿，不必一次填齐全部项目资料。

进入项目后的流程栏仍按 **Site analysis → Plan Studio → Simulation → Rendering → Boards** 排列，但每一步可跳转。Workbench 作为 Plan Studio 的编辑工作区，也可从任一分析结果“修改模型”直接进入。评审、报告与反馈是贯穿方案的成果层。

### 3.2 模式差异与三层机制

| 维度 | 默认路径：Simple | 可选覆盖：两种模式通用 | 完整控制：Advanced |
|---|---|---|---|
| 输入 | 地址；有几何研究时补可用模型；用途可沿模板或稍后指定 | 点击某个假设即可改一项 | 主动展开所有相关输入，支持自定义参数集与文件 |
| 天气 | 最近有效站点自动匹配、获取并校验 | 改选站点或上传 EPW，不必升级模式 | 完整站点信息、逐字段质量、时间轴与原文件检查 |
| 参数 | 只显示影响决策的摘要与阻塞项 | 改值、解释影响、恢复默认 | 引擎级白名单参数、网格和求解设置 |
| Workbench | “需要调整模型？”轻入口，按任务只展开相关工具 | 从某一窗、灯具、材料直接定位对象 | 完整类 Rhino 视口、图层、对象、属性、分析网格与验证面板 |
| 默认值 | 与 Advanced 使用同一个模板版本和解析器 | 同一覆写优先级 | 不因切换自动换更精细算法或不同物理模型 |
| 报告 | 默认快速汇报版，仍保留方法、关键假设与局限 | 可切换详细技术版 | 默认详细技术版；可选快速版 |
| 计算 | 根据所选研究配方运行 | 可独立选已支持的计算档位 | 更多配方控制；运行前仍做校验 |

模式仅修改 `uiMode`。Advanced→Simple 不删除覆写、Workbench 对象、文件、方案或结果；Simple 顶部保留“使用了 N 项自定义设置”及查看入口。切换本身不导致结果过期，也不自动重跑。

### 3.3 参数隔离与解析规则

每个项目复制并固定模板版本，而不是持续引用账户的可变默认值。账户偏好只用于创建新项目；更新模板需要预览差异，应用为新的项目配置修订，不追溯修改既有 Plan。

解析顺序遵循“先局部，后全局；同一作用域显式输入优先”：

1. 当前研究对某对象/房间的显式覆写；
2. Plan 中该对象/房间的显式属性，包括 Workbench 输入与已确认源文件属性；
3. 研究全局覆写；
4. Plan 固定的项目自定义配置；
5. 基于可用输入的推导结果；
6. 固定版本的用途/地区/年代模板；
7. 该研究配方的后备默认值。

参数页与 Workbench 修改同一条规范化属性记录，记录明确作用域；不能各自存一份并按“最后一次打开的页面”决定。存在显式冲突时提示选择要保留的值。用户输入必须先通过单位、范围和语义校验，“优先级高”不代表允许无效物理输入。

“恢复默认”移除对应覆写，重新解析当前 Plan 固定的默认链；显示恢复后的值和来源。已经运行的 Plan 不原地改写：创建工作草稿，保存为新的方案修订。恢复默认不会顺便更新到最新模板。选择“升级模板”是另一个可预览操作。

## 4. 三大分析类型与核心能力目录

### 4.1 分类规则

- **建筑分析**：场地、周边、体量、围护结构、整栋建筑、街区；包括建筑整体热工和能源性能。
- **室内分析**：房间、工作面、观察位置、家具/灯具布置及室内环境质量。
- **表格类型**：以逐时/汇总数据、非几何图表、比较、归因与交付图表为主要成果的任务。面向数据和交付，不另发明一套求解器。

一个研究的三维结果与数据表引用同一个 Run。建筑分析中的气候快捷卡可以跳转“表格类型→气候”，室内采光的“导出逐时表”可以进入表格视图。快捷入口不会复制研究或再次消耗计算。系统使用 `primaryCategory + domainTags + resultViews` 管理这种关系。

以下使用默认配置包标识：W＝天气/时间；G＝几何语义/网格；U＝用途/日程/负荷；M＝光学与热工材料；C＝舒适度；F＝风/CFD；E＝能耗与系统；R＝报告与统计。所有默认包均按第 6 节记录具体值、来源版本和覆写路径。

### 4.2 建筑分析：完整目标目录

| ID / 分析项 | 对应 Ladybug 生态能力 | 最小输入 | 自动推导/可选增强 | 主要输出 |
|---|---|---|---|---|
| B01 太阳路径、太阳位置 | LB SunPath / Day Solar Information | 项目坐标、标准时区、日期 | W 推导太阳向量；朝向来自 G | 太阳路径、方位/高度角、时刻表；无模型可用 |
| B02 外部直射日照小时与阴影 | LB Direct Sun Hours；HB Direct Sun Hours | B01 + 体量/遮挡 + 接收面 | G 网格、W 日期/时间步长 | 日照 h、阴影序列、时段差异；几何太阳研究不强制 EPW |
| B03 辐射、辐照度、天空矩阵 | LB Incident Radiation、Sky/Radiation Dome、Radiation Rose；HB Annual Irradiance / Cumulative Radiation | EPW/WEA 辐射 + 几何/受照面 | W 天空矩阵、G 网格、M 地面反射假设 | kWh/m²、W/m²、立面/屋顶分布；明确是否计算反射 |
| B04 天空暴露、遮罩、视域因子 | LB Sky Mask、View Factors、Human to Sky Relation；HB Sky View | 几何 + 接收区域 | G 采样/方向、明确天空暴露或投影天空可视因子的定义 | 天空遮罩、暴露率、SVF/视域因子，不能混用指标定义 |

## 5. Workbench：改造现有 Workspace，而非另做 CAD

### 5.1 页面与交互

复用现有 Plan Studio/Workspace 场景、命令系统与稳定对象 ID。

- 顶部：项目、Plan、保存/撤销/重做、模式、坐标/朝向、当前研究、运行按钮；持续显示草稿与结果状态。
- 中央：平面/透视/立面，支持单视口与双视口；滚轮缩放、平移、轨道、框选、对象吸附、尺寸输入、Gumball；Esc 退出命令，Tab 循环候选对象。
- 左侧：工具与相关资源；默认只展开当前任务需要的“窗/遮阳”“灯具”“家具”“材料”等。
- 右侧：图层/对象树、属性、模型健康、版本；选中结果问题可定位源构件。
- 底部：单位、楼层、坐标、选择状态、保存状态和任务进度。命令提示采用建筑操作语言，保留类 Rhino 操作习惯，不承诺完整 Rhino 几何内核。

### 5.2 图层与分析语义

| 图层组 | 对象/属性 | 下游使用 |
|---|---|---|
| Site / Context | 地块、地形、周边体量、植被及来源/估算高度 | 日照、辐射、风、室外舒适、排水 |
| Building / Envelope | 墙、屋顶、楼板、门窗、遮阳、对象稳定 ID | 采光遮挡、热工边界、气流开口 |
| Rooms / Zones | 房间、用途、层高、占用、热区映射 | 网格、能耗、舒适、通风 |
| Furniture | 位置/尺度、光学属性、可选质量/热容及资料来源 | 光遮挡、局部气流、内热容、净空；按 recipe 筛选 |
| Lighting | 灯具位置、安装高度、配光文件、功率、控制/日程 | 人工照明、调光与照明负荷 |
| Materials | 可绑定对象/面的属性集合 | 各求解器读取对应物理参数 |
| Structure | 梁柱板/支撑、轴线、截面、材料、连接、荷载、约束 | 结构求解器；其他分析只读取需要的几何 |

图层负责组织，分析语义负责计算。移动到名为“Structure”的图层，不自动让任意网格成为有效结构梁；隐藏图层不等于排除计算。分别提供“视口可见”和“参与该分析”，记录两者。

### 5.3 构件属性与跨分析传递

同一材料卡分为光学（反射率、可见光透射/BSDF）、热工（层构造、导热率/密度/比热、U 值/SHGC 等）、声学（分频吸声）、结构（E、G、密度、强度等级）子栏。渲染颜色/纹理无法推出这些物理属性，彼此不串用。

灯具模型外形不等于配光。没有 IES/LDT 或明确的简化配光时，概念模板必须标注；光通量、输入功率、调光日程分别保存。用户放置灯具后，选择“由灯具汇总房间照明负荷”或“保留面积负荷模式”，避免模板 LPD 与显式灯具功率相加两遍。

家具不是能耗、DF 或外部风分析的普遍必填项。默认可用空房模型+明示的内部质量模板；若用户选“典型办公布置”，生成的家具作为带来源的模板对象，可删除/替换。放置家具后先判断是否影响该配方，不能声称任何家具改动都会提高所有仿真精度。

语义适配器将同一个 Plan 编译为不同输入：Radiance 场景与传感器、HBJSON/Dragonfly、OpenStudio/EnergyPlus、OpenFOAM case 或现有浏览器 scene。分析参数页读取既有属性，只展示缺失与研究专用覆盖，避免重复填写。

### 5.4 编辑、差异与两种模式

每次命令记录稳定对象 ID、操作、旧值/新值、单位、作者/时间、来源以及影响的研究。撤销/重做也在事件链中，保存方案时形成不可变快照。导入更新优先按源 ID 对应，无法匹配的对象标为新增/移除或待确认，不编造连续性。

Simple 默认收起复杂面板，结果页提供“调整这扇窗”“添加遮阳”“更换材料”的上下文入口。Advanced 展开完整图层、对象、材料、网格和边界条件；两种模式共用同一命令与数据模型。

## 6. 最小输入、默认来源与透明推导链

### 6.1 逐研究的最小输入

| 用户拥有的信息 | 可以自动准备 | 仍不能自动宣称完成 |
|---|---|---|
| 地址 | 天气、气候图、太阳路径、风玫瑰 | 具体建筑室内采光、局地 CFD、能耗 |
| 地址 + 体量 | 日照、遮阴、辐射、初步外部风/天空研究 | 有真实房间/开窗细节的室内研究 |

### 6.2 处理流水线

地址解析 → 固定项目坐标与标准时间关系 → 获取/校验 EPW → 导入源模型与单位 → 建立坐标变换 → 非破坏性几何健康检查 → 图层/对象语义映射 → 识别房间/热区与相邻关系 → 应用固定模板/显式属性 → 生成传感器与边界 → Workbench 可选增强 → 按研究判断就绪 → 保存输入/推导快照 → 运行。

清理允许自动处理可证明不改变语义的重复点、退化面、法向等；关窗、补墙、猜支座或把单层网格改成闭合热区属于设计/语义变更，应预览并记录，不能静默执行。源模型不改动，保留原始与分析副本及变换。

就绪状态至少为：缺输入、可做筛查但有限制、满足所选配方输入、运行中、成功、失败、已取消、旧条件结果。状态按每个研究分别判定；缺结构材料不阻塞气候分析。

### 6.4 推导链透明度与来源模型

概览用一句话说明：“天气来自 X 站，距离 D km；用途为办公模板 V；N 项自动推导、M 项用户覆盖；本次研究有 K 个限制”。点击任何摘要打开依赖树和具体字段，不要求用户阅读整页技术表才能运行。

不能把用户要求的六种来源标签做成互斥枚举：一个值可能既是“平台默认/推导”，又通过“Simple 自动匹配”取得。采用三个维度：

- valueOrigin：平台默认 / 推导所得 / Workbench 用户输入 / 用户覆写 / 源模型已确认属性；
- acquisition：Simple 自动匹配 / 用户选站 / 用户上传 / 源文件导入 / 手动填写；
- modeAtAcquisition：Simple / Advanced。

报告按需组合显示“推导所得·Simple 自动匹配”“用户覆写·Advanced 用户上传”；Simple 内上传则如实写“用户覆写·Simple 用户上传”，不伪造 Advanced 来源。

每条记录保存：parameter path、作用域、有效值/单位、原值、来源 URI/文件 hash、模板/规则版本、父输入 IDs、取得时间、作者、覆写/恢复事件、质量/置信依据、适用研究。不能用无根据的“95% 准确”当置信说明。

### 6.5 示例 A：Simple 自动 EPW

1. 用户输入地址并确认正确位置；系统创建项目，名称自动生成。
2. 从站点目录查询候选，默认选最近有效站；显示站名、距离、海拔（有资料时）、数据期/类型、目录日期、发布者、完整性与“按距离初选”的理由。
3. 自动获取并校验文件；成功后固定原文件 hash、站信息、时间轴。若最近站文件失败，可尝试下一个有效候选，但必须说明实际选站与原因。
4. 提取温度、湿度、辐射、风向/风速；自动生成风玫瑰、月图、逐时表。无模型时显示“风气候已准备，局部风环境待体量”。
5. 用户有模型时自动准备现有风筛查所需方向/速度；全年风舒适选择多方向任务集及权重。CFD 仍按自己的就绪契约检查，不由一张风玫瑰直接生成结论。
6. 用户点击“换气象站”可比较附近站/上传；保留旧天气与旧结果，创建新条件修订。

失败：地址不唯一→列候选；站点远或地形差异→清楚提示可改；网络/发布者不可用→保留草稿与重试/上传入口，不回退到虚构泛用天气并称为项目结果。沿用现有远站审查规则时必须显式展示，不反复要求所有正常项目确认。

### 6.6 示例 A′：Advanced 选站/上传 EPW

用户选择站点或上传 EPW → 校验文件结构、头信息、地理/时区、DATA PERIODS、时间步长、逐时连续性、重复记录、闰日、缺失哨兵值、研究必需字段 → 生成与 A 相同的 WeatherAsset → 同一推导与就绪流程。

首期生产路径支持完整逐时 8760/8784；不截断 8784 为 8760。对闰年而 recipe 仅接受 8760 的情况，创建带转换记录的非闰副本并明确排除规则，原文件保留；需要用户接受转换的结果状态清楚。子时段/部分年度文件可以保存原件，但只有兼容配方可运行；不兼容时列出需转换内容，不默默重采样。

缺字段按研究阻塞：缺 DNI/DHI 阻塞气候辐射/全年日光，不必阻塞数据完整的风玫瑰。静风/缺测/异常值分别处理，完整率与有效样本分母写入图表。天气时间和能量字段遵循 EPW 定义，不能把 Wh/m² 直接当任意时间步长的 W/m²。[EnergyPlus EPW Data Dictionary](https://bigladdersoftware.com/epx/docs/24-2/auxiliary-programs/energyplus-weather-file-epw-data-dictionary.html)

上传天气不改变项目坐标、模型朝向或场地。上传文件的站点和项目位置差异显示为来源说明。

### 6.7 示例 B：地址、模型、用途→建筑分析

用户确认地址，导入 3D 模型，指定基本用途或沿用模板 → 系统读取单位/朝向/图层/对象 IDs、建立非破坏性副本、检查几何、识别体量/空间/开窗、应用项目模板、生成评价区域与网格 → 显示“可以运行的研究”和阻塞原因 → 用户点击“运行默认研究包”。

默认研究包由任务决定：体量推敲推荐太阳/遮阳/辐射；室内采光推荐时点与全年指标；热模型有效才推荐负荷/舒适。**不默认运行全部 22 项或所有 LBT recipe。** Workbench 作为“提高模型适配度”的可选入口；仅当语义有歧义或必要事实缺失时要求补齐相关项。

无法识别房间/开窗时可继续体量研究；不能把漂亮的三维显示网格当作有效热模型。没有明确真北的模型应标记方位假设；确认一次后被所有相关研究复用。

### 6.8 结构分析场景

用户在 Workbench 的 Structure 图层建立/导入梁柱轴线、楼板/支撑，给构件组分配材料等级与截面，设置节点连接/释放、支座、荷载及组合。平台可以从长度、截面和密度算自重，建议轴网/初始截面，检查模型是否连通；它无法从室内家具、立面纹理或地址推出可靠支座与受力系统。

运行前检查材料 E/密度/强度与截面完整、轴线/节点连接、重复构件、自由度与约束、荷载单位/方向/组合、机制/奇异刚度、荷载路径；缺失问题可点击定位到对象。展示“3 根梁缺截面、2 个节点支座未定义”，提供“定位并填写”或“应用可检查的概念模板”入口。只设置钢/木的渲染颜色不通过材料检查。

未满足时只阻止结构研究。自动建议可生成待审的结构方案草稿；没有完整适用的分析/校验规则时，不将自动截面变化当作已经验证的结构设计。

### 7.1 每一环的最少动作、系统工作与失败行为

| A/B 复核 | 选择指标/是否写入报告 | 双面板、共用标尺、delta、差异/可比较性检查 | 不兼容结果明确阻止直接差值或注明情景变化 |
| 交付 | 选模板，点生成 | 生成可编辑 PPTX、PDF、受控网页报告及证据包 | 导出失败保留 ReportSpec 与已成文件，单独重试 |
| 客户反馈 | 客户在具体页/对象评论 | 记录报告修订、Plan/Run/对象位置，形成修改事项 | 离线可保存/导入反馈；不能把未收到的意见自动编成反馈 |
| Plan C | 选择采纳事项或编辑 | 从选定方案派生 C，保留反馈关联、重跑相关研究和更新报告 | 冲突事项并列展示，不覆盖已有 A/B |

### 7.2 可执行建议的数据与机制

建议至少包含：触发指标/目标来源、空间范围、候选影响参数/对象、证据等级、具体变更 patch、前置条件、约束、预期方向、需要重跑的研究、代价、撤销方式和父 Plan/Run IDs。

例：某办公室选用的遮阳目标未满足，受阳区域集中在两扇南窗附近。系统不能直接断言“窗宽是唯一原因”。它可提出“在这两个已识别窗上增加 0.40 m 水平遮阳”的设计候选，写入带宿主关系的遮阳对象，重跑日照/全年采光以及已启用的热研究，再显示采光、直射与冷热需求的实际变化。0.40 m 只是候选参数；没有运行结果前只说明方向和潜在权衡。

实现分两层：规则/敏感性/小范围受控试算生成合法变更；语言模型可解释结果、整理建议文案，但不制造数值、规范条款或越过几何约束。优先提供有版本定义的操作：加遮阳、改遮阳深度、改窗高/窗宽、替换已验证材料、改灯具/控制、调整可开面积。

“采纳并运行”需要一个事务：校验 A 与建议所基于的输入 hash → 深复制/持久化 B 和 lineage → 原子应用 patch 与变更日志 → 建立 RunGroup/任务 DAG → 调度 → 回传结果 → 生成比较。A 不变，重复点击使用幂等键不会生成重复方案或重复收费任务。

### 7.3 自动跑完的边界和执行方式

- 默认研究包里受影响任务全部自动运行，未受影响任务可引用具有一致输入 hash 的结果；不因采纳一条建议自动启动整个能力目录。
- 必需事实完整、执行环境已就绪的建议才展示可用的“一键采纳并运行”；需要新增事实的建议展示可编辑草稿及缺项，不能点击后再假装完成。
- 当前浏览器批量任务依赖页面保持打开，当前本地引擎依赖导出/运行/导入。它们可以保留，但**不能用于宣称已满足“无人干预自动跑完”**。
- 面向完整闭环的目标需要托管队列/worker，或用户先配置的受信计算代理；设置成本在 onboarding 说明，之后应用建议无需再手动搬文件。
- 云计算在已设预算上限内自动完成，超限前显示任务明细与预算状态，不偷偷降精度/换算法。项目可预先选择自动运行额度，减少日常重复确认。
- 不保证 B 一定更好。B 出现退化时照实保留，提供回到 A/试另一候选，不能仅凭“建议已应用”标成功。

## 8. A/B 比较、差异归因和方案即版本

### 8.1 界面与数值规则

左右各有 Plan/Run 选择器、3D/结果图或非几何面板；视角联动、同一单位/图例范围/时间筛选。统一标尺以 A/B 联合值域或明确固定范围生成，并保留裁剪提示。

指标卡显示 A、B、绝对 delta、相对变化、评价方向/区间和目标来源。统一公式：绝对差为 B−A；相对差为 (B−A)/|A|×100%。A=0 时相对差显示“未定义”；百分比指标的绝对差用百分点，例如 50%→60% 为 +10 个百分点、相对 +20%。缺失值不当作零。

“更好/更差”由目标定义，不由数值增减决定：EUI 较低可能好，UDI 在适宜区间更好，日照/温度/风速常有上下限。无目标时只显示增减；颜色不能代替目标说明。

### 8.2 可比较性与差异热图

比较前检查方法/引擎/recipe 版本、天气 hash、时期与时区、占用掩码、网格/评价区域、楼层、材料、HVAC、阈值和归一化面积。分开显示：

- 固定条件相同、设计不同：适合方案变化比较；
- 天气/用途/控制等也改变：可作情景比较，明确差异；
- 缺少证据或不同方法/指标：不可直接比较。

几何差异着色显示增/删/改；结果差异着色显示基于目标的改善/退化，两者不能用同一图例混淆。只有相同物理位置/评价域有可靠匹配的传感器才逐点相减；改变平面、网格或房间时，可选择共同参考网格重跑，或明确插值方法/不可匹配区域。新增/移除区域用斜线/缺值，不能最近邻随意填满。面积百分比使用一致区域或明确列出分母变化。

### 8.3 归因与报告选择

差异表列出对象/参数、A 值、B 值、来源、影响的计算、结果 delta、证据等级、是否进入报告。可按行定位几何，可按结果反查输入。

一次修改多个参数时，只能说明它们共同变化；需要归因比例时增加单因素消融、受控方案或预先定义的敏感性试验，记录交互效应与额外算力。不能从 A/B 两次结果倒推出每个构件贡献了多少。

### 8.4 Plan、Run 与 lineage

Plan 是一次命名的设计承诺，包含模型/场地/参数/推导链快照、备注和父方案/父修订。Run 是某 Plan 上某分析的结果快照：一个 Plan 可以有多个分析和多次 Run。结果可追加，既有记录不可覆盖。

工作草稿可以持续编辑；点击运行自动冻结为 PlanRevision。A/B/C 是用户可读的方案名与 lineage，首期 UI 只突出双栏，但数据结构支持多个分支和多级派生。

回滚是“从历史快照恢复为新草稿/新修订”，不删除后继历史。命名、备注、分支、团队共享需有权限和作者信息。共享条件、模板或材料改变时，通过依赖 hash 将当前不适用结果标为旧条件结果，保留原值和当时适用性。只改变界面模式、视角或注释，不应让物理结果过期。

## 9. 报告、PPT、网页与反馈

### 9.1 统一交付结构

报告从保存的 Plan/Run 构建，不从屏幕上可能已变化的临时状态截图拼接。一个 ReportSpec 产出三个渠道，默认包含：

1. 项目概况：名称、客户、用途/阶段、地址、位置、模型与版本；
2. 天气：站点、距离、类型/数据期、EPW 来源/hash、为何采用；
3. 方案说明与 lineage：A→B，具体变更；
4. 关键假设与来源标签、覆盖项、缺项和研究局限；
5. 指标对比、达标/目标状态、分母与计算方法；
6. 同视图/同标尺并排结果与可用差异图；
7. 输入差异和经证据支持的归因，区分候选原因/已验证影响；
8. 结论、取舍、下一步与待确认事项；
9. 技术附录：方法/引擎版本、网格、时间、日程、材料/系统、日志与数据导出清单。

快速汇报版拟 6–10 页，技术版按研究规模增加附录；页数是产品模板预设，不是物理默认。两版均显示关键假设、方法、输入版本和局限。品牌设置为项目/组织级 LOGO、颜色、页脚和作者，不改数值内容。

### 9.2 格式要求与更新机制

- **PPTX**：文本、表格与汇总图表使用可编辑元素，平面/三维结果可为带来源的图片；底层指标数据附在工作簿或证据 CSV 中。不能把每页都做成大图后称“可编辑 PPT”。
- **PDF**：用于稳定审阅，保证中文字体、分页、图例/单位可读；与 PPT 和网页使用同一个 ReportSpec。
- **网页分享**：报告快照使用私有/受控链接，可设置接收范围、有效期/撤回；创建分享是明确动作。不能直接分享指向本地 localStorage 的地址。
- **证据包**：Plan/Run JSON、CSV、图、引用资产/许可、计算输入及依赖清单。当前 EPW 不随 JSON 备份是必须补齐的实际缺口；许可不允许分发的资产保留来源与恢复说明，不能保证一个空引用包可离线重现。

每个章节保存依赖 hash：B 只改灯具，则标记人工照明、照明能耗、指标汇总/结论相关章节重新计算/生成；天气、A 方案等未变章节复用缓存。输出依然是一个新报告修订，而不是悄悄覆盖已经发给客户的文件。用户在 PPT 外部手动改过的内容，不承诺能无损自动合并；支持导出新版本并给出变更清单。

生成失败保留 ReportSpec 与日志，分渠道重试；截图失败显示缺图，不用示意图替代计算结果。已有 PDF/HTML/CSV/JSON 导出继续可用。

### 9.3 客户反馈回到 Plan C

网页按页/指标/对象创建反馈，绑定 reportRevisionId、Plan/Run IDs、构件 ID、视点和时间；状态为待处理/采纳/部分采纳/不采纳/已验证。客户不必进入复杂工作台。

建筑师勾选采纳事项，从 B 派生 C，进入已定位的 Workbench/参数项；只有能表达成合法 patch 的事项才能一键应用，主观意见保留为任务。报告的“反馈回应”说明改动、结果与未解决项。提交/通知客户由用户明确动作触发，不默认发送邮件或公开项目。

## 10. 技术架构与现有代码迁移

### 10.1 最小可落地架构

现有页面/Workbench → 项目与参数解析服务 → 分析语义模型编译器 → 按输入依赖的作业 DAG → 浏览器/本地/托管 worker 适配器 → 规范化结果存储 → 建议 patch 服务 → Compare / Tables / ReportSpec / Feedback。

继续保留静态前端作为应用外壳；托管长任务与分享需要服务端持久存储、队列和对象存储。可复用仓库已有后端配置，但必须检查权限和真实部署状态再选型。不能仅靠重命名路由完成这一架构。

| 领域对象 | 必须保存的信息 |
|---|---|
| Project | 名称/描述/用途/客户、uiMode、模板版本、自定义参数集、成员、资产引用、当前草稿 |
| PlanRevision | parentPlanId/parentRevisionId、模型与场地快照、effective parameters、推导 DAG、输入 hash、作者/备注、反馈/建议来源 |
| Asset | 原文件、hash、单位/坐标、来源/许可、版本、可恢复性；EPW 与模型不只存文件名 |
| ParameterRecord | path/scope、值/单位、来源与取得方式、依赖、默认基线、覆写/恢复历史 |
| Recipe | 输入/输出 schema、supported mode/quality、引擎镜像、约束、成本和验证用例 |
| Run / RunGroup | PlanRevision、recipe/engine、输入/输出 hash、作业阶段/日志、失败/取消、状态、生成时间 |
| ResultField / Metric | 单位、空间/时间索引、面积/占用分母、缺测掩码、评价目标、方法元数据 |
| Recommendation | evidenceRunIds、目标、patch、前置 hash、影响依赖、预算/执行状态 |
| ReportRevision / Feedback | 章节依赖与资产、选用 Run IDs、分享权限、反馈锚点与采纳记录 |

关键命令可定义为 `prepareStudy`、`resolveParameters`、`freezePlan`、`submitRunGroup`、`applyRecommendationAndRun`、`compareRuns`、`buildReport`、`deriveFromFeedback`；初期可为模块接口，后期为 API。保持同一契约，防止浏览器版和云版产生两套语义。

### 10.2 引擎集成原则

- 使用 Ladybug/Honeybee/Dragonfly 的 schema/库和配方能力，而非要求每个用户打开 Grasshopper。源端导出插件或连接器是可选增强。
- 不同引擎容器锁定依赖与操作系统兼容性；Butterfly/OpenFOAM 的版本/接口需独立原型验证，不能仅因官方页面列出 CFD 就承诺可直接部署最新版。[Butterfly 官方说明](https://www.ladybug.tools/butterfly.html)
- Radiance、EnergyPlus/OpenStudio、CFD 和结构求解器各有独立 adapter、错误状态、输入校验和验证数据。保留现有浏览器筛查作为显式配方。
- 原始模型、分析代理、求解器输入、结果和报告分别保留 hash 与转换链。复杂模型的简化须有方法、误差/局限说明，不静默替换为盒子。
- 暴露的是受支持 schema 下的底层参数；Advanced 任意脚本/命令/插件不属于默认产品契约，扩展任务进入受隔离执行环境。

### 10.3 依赖缓存、作业与一致性

缓存键包含 model/semantic model、有效参数、天气、网格/时段、recipe/engine 版本；图例、显示模式和项目 UI 模式另做展示缓存。只改日光阈值可复用照度矩阵；改玻璃光学属性重算采光；改热构造重算热研究；同一玻璃更换同时影响光学与热工时两类均失效。

作业状态覆盖 queued/running/succeeded/failed/cancelled，输入在提交时冻结。失败不写成功数值；重试幂等、不覆盖历史；取消与实际资源终止状态分别记录；不能因界面关闭就承诺远端计费停止。重型任务持久化进度并可恢复。

### 10.4 增量迁移顺序

1. 确认线上源提交、各工作树差异和未提交改动；本轮未触碰已有修改。
2. 以新增 schema/adapter 包装当前 project/sharedConditions/version/run，保留原 IDs、链接和导出文件。
3. 创建 legacy provenance：无法恢复的来源标为“历史未记录”，不倒填成平台推导。
4. 新的项目与模式入口通过可回退开关上线；旧入口跳转时保留 project/version/study 参数。
5. 先把日照/采光接入统一契约，再逐个适配现有其余工具；迁移期保留旧工具可直接用。
6. 确保 EPW/模型/结果与本地参考引擎记录可完整备份、导入和恢复后，再扩大云共享。

## 11. 实施优先级、取舍与商业可持续性

### 11.1 核心、辅助、延后和移除

| 决策 | 内容 | 取舍原因 |
|---|---|---|
| 核心 | 项目隔离、模式、来源链、模型语义、日光/遮阳闭环、Plan B 自动运行、A/B、报告/PPT | 直接减少参数重设和手工汇报，形成可重复付费价值 |
| 核心逐步补齐 | 年采光/眩光、热需求/能耗/舒适、CFD、街区 | 满足完整核心能力目标；按模型和计算基础依赖扩展 |
| 辅助 | Workbench、兼容资源、导入更新、室内 Rendering、Boards、现有专项工具 | 服务真实修改和交付；不以编辑命令数量衡量价值 |
| 延后 | 完整 Rhino 替代、任意 Grasshopper 执行、复杂结构优化、详细 HVAC、区域能源网络/GHE/电网优化、全面认证包、手机专项设计 | 成本和输入要求高，先建立统一数据和验证基础 |
| 合并/从默认首页移除 | 重复模拟卡、按底层算法命名的入口、重复 EPW/材质表单、无任务关联素材墙、假完成标记 | 降低认知与重复输入；保留能力和深链接，审计后再退役旧页面 |

Resources 优先展示当前任务兼容、可预览、授权清楚且带必要物理属性的材料/灯具/构件。仅有渲染外观的资源明确其用途；不把下载量与素材数量当性能产品核心指标。

Rendering 保留独立入口，先做好室内：指定家具/参考→指定目标/区域→生成真实结果→A/B→导出；外部服务、付费和几何保真限制明示。效果图不进入性能验证证据。Boards 使用已保存的图表/渲染/图纸，不要求用户重新上传一遍。

### 11.2 按验收关口推进

| 阶段 | 交付与依赖 | 阶段退出条件 |
|---|---|---|
| P0A 基线与数据契约 | 线上源确认、22 项迁移表、参数/来源/Plan/Run schema、资产恢复 | 两项目不串参；历史备份可恢复；旧链接可用 |
| P0B 默认路径 | 我的项目、统一创建、Simple/Advanced、单项覆写、EPW 入口整合、三类导航 | 地址项目完成真实气候成果；模型项目只补该研究必需信息 |
| P1 首个完整闭环 | 复用日照/采光及 Workbench，限定合法窗/遮阳 patch，自动 B/重跑/A/B；扩展现有报告到 PPTX | 一个真实项目从输入到可编辑 PPT/PDF/网页反馈并生成 C，数值/来源一致 |
| P2 高控制光环境 | 接入全年 HB-Radiance、DA/cDA/UDI、适用 sDA/ASE、眩光、动态遮阳、灯光 | 与固定参考案例比较且有收敛/方法限制；浏览器筛查与参考引擎结果不混算 |
| P3 热工与舒适 | 有效热模型编译、用途模板、构造、Ideal Loads→HVAC、PMV/自适应、光照控制耦合 | 能量平衡/输入一致、真实案例验证；热需求和电耗区分 |
| P4 风与街区 | OpenFOAM/Butterfly 适配、多方向风评价、Dragonfly/UWG/街区能耗 | 网格/域/收敛/统计测试通过；衍生 EPW 与原文件均可追溯 |
| P5 生态扩展 | 详细 HVAC、标准配方、区域能源/电网/经济优化、其他专项自动建议 | 每项独立输入/运行/导出/成本验收；不因入口上线就标核心覆盖完成 |

P1 可先用已验证现有配方打通，但必须明示筛查级别。面向真实 Honeybee 目标的产品承诺，需 P2/P3 适配验收后发布。“全部核心已覆盖”只能在能力注册表中所有约定核心条目均通过关口后使用。

### 11.3 成本与商业模式

免费层可继续提供轻量浏览器研究/基础导出；付费价值优先落在持久项目、协作、完整追溯、品牌报告、更新交付和托管任务。具体价格需要用户研究与实际成本，不从旧价格页面直接推定新套餐。

计算成本按“任务数×平均 CPU/GPU 时间×单价 + 存储/流量 + 失败/重试与运维”核算。先记录实际案例数据，再设置免费额度与计算预算。缓存天空/照度/未变依赖、只重跑受影响研究、先试少数候选，再扩大参数扫描；不默认后台生成几十个方案，也不承诺无限 CFD。
