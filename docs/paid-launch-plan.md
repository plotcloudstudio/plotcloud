# PlotCloud 收费上线计划

基于 GitHub main `76854eb`，制定于 2026-11-19。执行状态以此文件与实际验收记录为准。

## 首批用户与交付

首批假设是建筑师和建筑学生在方案评审前，把现有模型导入 PlotCloud，计算方案 A/B，提交带输入条件、方法、图表和数值的报告。优先减少重新导入、重设参数和手工整理报告。用真实模型完成任务与恢复成果来验证价值。

核心为模型输入、计算、版本比较、报告、保存与恢复。家具、插画和渲染辅助表达。托管 CFD、完整年度能耗、自动订阅和多人协作延后。收费承诺仅覆盖已经验收的任务，各分析保留自己的方法和适用范围。

- [x] 修复报告来源筛选、报告预览和视窗工具可见性，通过当前 Workspace 入口验收。
- [x] 清理引用已移除服务的检查，接入现有浏览器渲染检查，保留参考引擎文件交换验收。
- [x] 保留动态墙，验证系统减少动态效果与手动播放、暂停。
- [x] 使用明确设置坐标的 Courtyard 输入模型实际计算 A/B，验证保存、重载和 PDF/HTML/CSV/JSON 下载。
- [ ] 验证参考引擎流程，区分实际执行、环境依赖和未验证项目。

验收成果是可复现的命令、通过记录和明确的剩余问题。第一阶段不代表完成商业上线。

## 第二阶段　形成首批可售计算范围

- [ ] 为每项纳入收费的分析指定场景、输入、输出、限制和失败条件。
- [ ] 建立基准案例与参考答案，记录版本、容差及网格/采样敏感性。
- [ ] 扩大真实建筑和导入几何的覆盖，验证场地、朝向、时区、单位及接收面。
- [ ] 核对结果图、图例、表格、CSV、报告数值和原始结果一致。
- [ ] 验证输入改变后历史结果的适用状态，以及不同条件下比较的提示。

采光 DF 的 Radiance 对照记录与年度 sDA/ASE 的验证分别记录。风环境、结构与疏散等按各自已验证的方法和范围交付。

## 第三阶段　账户、权限与成果保障

- [ ] 用两个普通测试账户验收注册、确认邮件、找回密码、登录与退出。
- [ ] 验证项目、版本、结果与会员的跨账户隔离。
- [ ] 验证会员授予、续期、撤销、过期和网络失败。
- [ ] 验证跨设备恢复，覆盖模型、天气文件、图表和渲染图片。
- [ ] 明确大项目限制、同步失败状态和支持流程。
- [ ] 演练备份恢复、并发修改与部分失败后的重试。

公开接口只读检查不能代替真实账户验收。此阶段需要可使用的测试邮箱、后台权限及 SMTP 配置证据。

## 第四阶段　商业部署与首批订单

- [ ] 确定商业托管与正式地址，完成旧地址项目迁移和 Auth 回调验收。
- [ ] 验证正式注册邮件、错误监控、服务故障提示及发布回退。
- [ ] 为公共地图服务落实全站请求限制、缓存和可替换来源。
- [ ] 确认卖方信息、价格、税费、服务期限、退款与支持方式。
- [ ] 完成一笔经过授权的测试订单及开通、到期、退款处理演练。
- [ ] 由首批真实用户完成项目与报告，记录失败、耗时和支持成本，再确定扩大收费范围。

先沿用已存在的人工核款与账户开通流程。自动订阅单独验收付款事件、幂等、失败付款、取消和退款。域名采购、收费服务购买、真实客户交易及基础设施迁移在具体结果可审阅后确认。
