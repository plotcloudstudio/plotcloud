# PlotCloud 全站 UI 统一计划

状态：共享 UI 层及页面适配已实施；验收范围与发布结果见 `ui-unification-release.md`。本阶段目标是全站一致性，不扩展分析引擎、账号、支付或云存储。依据当前仓库 `7db4c21` 的页面、路由、样式和测试制定；页面实际渲染与外部服务状态需在实施时逐项验收。

## 1. 业务目标与完成定义

主要用户是使用现有 CAD、Rhino、Revit 工作流程的建筑师，同时支持建筑学生。统一后的产品应支持：场地与模型 → 方案版本 → 分析设置 → 结果比较 → 渲染与图板交付。用户切换工具时不应重新学习导航、选中、设置、保存、运行和导出的位置与规则。

“全部统一”完成需同时满足：

- 新版网站、旧站过渡入口和独立/内嵌工具使用同一套基础视觉规范。
- 名称、导航层级、项目上下文、主题、状态和基本操作一致。
- 各工具的必要参数、专业图例、快捷键与实际能力得以保留。
- 路由清单中每一项有验收记录，不能用一个示范工具代表全部完成。
- 公开首页保留已确认的无框、大比例 CN Tower 模型；保留鼠标互动和 Sun → Wind → Rain → Sound 返回轮换，不重新加入可见控制条。

## 2. 范围清单

| 区域 | 当前范围 | 统一重点 |
|---|---|---|
| 新版页面 | `mvp/js/pages/` 的 home、workspace、workspace-v2、simulations、results、resources、pricing、login、account，及 `mvp/workspace.html` | 站点导航、标题层级、公共组件、项目状态与入口 |
| 旧站与过渡路由 | `index.html`、`site-shell.css/js` 生成的公开页面、项目和工具入口 | 保留现有地址及链接；让过渡路径保持品牌与返回位置一致 |
| 建模/场地工具 | `emb/modeler.html`、sitectx、tracer、furniture、facade、detaillab、doors3d、stairs3d、topo | 模型主视口、对象/楼层/图层组织、属性面板与公共工具栏 |
| 分析 | SIMS 目录中的 14 个入口，逐一映射到实际工具；相关 HTML 包括 sunhours、daylight、wind、vent、stormwater、acoustics、spacesyntax、evac、isovist、views、cameras、structure、span | 输入、运行、结果、图例、导出位置与状态规则 |
| 渲染与展示 | architectural-render、render、composer、studio、atlas 的实际路由和用途 | 输入/预览/历史/导出以及通用控件，不覆盖作品本身的排版与字体 |
| 首页独立场景 | `hero/` | 日夜主题、响应式、可访问性；维持无框展示 |

入口与物理文件并非一一对应。例如 `emb/modeler.html` 是 Plan Studio；不能把 `emb/studio.html` 的文件名直接当作同一工作区。第一批建立完整 URL → 页面 → 实现文件清单，覆盖未列出的旧站动态路由。

## 3. 统一规范

### 视觉基础

- 品牌：沿用 PlotCloud 标志与红色主操作；公共界面不引入额外装饰性色系。
- 字体：界面使用统一的 Inter / Noto Sans / 系统字体回退组合；数值、尺寸、坐标与代码使用统一等宽字体。字体服务不可用时仍可读；不新增必须联网的字体依赖。作品画布允许保留用户选择的字体。
- 字号：桌面正文 14–15px、辅助文字 12–13px；工具面板标题 14–16px、页面标题 28–40px。展示性大标题只用于首页和少数介绍页。
- 间距：采用 4/8/12/16/24/32px 阶梯；相同层级使用同一间距。
- 控件：常规操作约 40px 高，密集桌面工具约 32px；触控模式至少 44px 可点击区域。明确主、次、文字、危险操作的层级。
- 形状：按钮和输入框以 6–8px 圆角为基础，常规面板 8–12px；胶囊形用于状态和分段选择，不再用于全部控件。
- 层次：通过背景、细分隔线和间距组织；阴影主要用于浮层。首页模型继续无边框。
- 图标：统一线性图标、尺寸和线宽；常用动作使用同一图标及名称。关键操作附文字或可访问名称。

### 颜色与主题

使用语义化变量统一 page、surface、viewport、text、muted、border、primary、selection、success、warning、danger、focus。浅色和深色成对定义；保留现有默认主题，并统一记忆与页面间传递。

品牌主操作、对象选中、错误和专业结果不能依靠同一个红色区分。Sun/Wind/Rain/Sound 的颜色仅作为对应示意语义；已有热图、阈值、工程图例和导出结果保留其专业含义，不能因换主题而改变数值含义。iframe 单独打开与内嵌时都必须正确应用主题。

### 导航与页面结构

建议公开导航统一为 Workspace / Simulations / Projects & Results / Resources / Pricing。已有功能保留可达。Workspace v2 经任务验收后确定主入口，另一个入口移入内部评审或兼容菜单；不直接删除实现。

工作区公共结构：顶部项目/版本/楼层/保存状态；左侧场地、模型与图层；中央模型或图面；右侧选中对象属性或当前任务设置；视口附近放视图与图例。分析、建模、渲染可按任务调整面板数量，不强行压成完全相同布局。内嵌工具不重复显示两层站点导航。

### 交互与文字

- 统一导入、保存版本、运行分析、比较、导出、撤销/重做、重置视图等名称和行为。
- 参数始终显示单位；必填项、输入缺失、无选中对象和不可用操作有明确说明。
- 保留已有快捷键，解决新增冲突；鼠标、键盘和触控均可完成关键动作。
- 加载、空白、失败、成功、未保存、旧结果和不可比较状态使用公共样式，错误提示提供下一步。
- 状态词基于真实能力：Mock、完整工具、计划中、保存在本浏览器不能混用。只调整展示，不将原型包装为生产服务。
- 尚未实现的结果失效判断、跨工具传参和服务器保存，登记为功能依赖；不能用静态徽标假装已完成。

## 4. 执行批次与验收门槛

| 批次 | 工作 | 交付与进入下一批的条件 |
|---|---|---|
| 0：完整清单 | 梳理所有路由、独立/内嵌形态、主题、共享/特有控件和现有测试；记录当前截图、用户数据和功能基线 | 页面清单每项有归属、实现文件、主题状态和验收方式；差异与功能依赖已记录 |
| 1：公共基础 | 建立设计变量、控件样式和组件展示页；定义导航、主题和状态协议 | 在一个网站页面、一个建模工具、一个分析工具中验证同一规范；两种主题、焦点、字体回退和基本任务通过。必要视觉方案在改页面前展示 |
| 2：站点与入口 | 迁移全部新版页面和旧站过渡外壳；统一公开工作区入口、页面标题和表单 | 9 个新版模块、独立工作区入口及旧站清单逐项验收；已有路由、项目与主题不丢失 |
| 3：建模与场地 | 优先 Plan Studio 与工作区，再迁移其余场地/建模工具；复用公共工具栏、属性与状态组件 | 导入→选择/编辑→保存版本→重新打开→导出通过；单位、楼层、快捷键和视图行为正确 |
| 4：分析与比较 | 日照/采光作首批参考，再覆盖全部 14 分析入口与 Results | 各入口核对输入→实际执行→结果理解→导出；不能执行的项目记录外部依赖或已确认缺陷，不能标为通过；所有图例、比较提示和主题通过 |
| 5：渲染、展示与资源 | 覆盖渲染输入、资源选择、方案历史、图板、参考、库、账号及定价的遗漏项 | 输入/选择/预览/返回/导出按已有能力验收；资源格式与授权信息清楚；不改用户作品内容，不虚构付费能力 |
| 6：全站收口与发布 | 路由遍历、跨页连续任务、回归、样式残留和双主题检查；分批发布 | 清单无未解释遗漏；相关自动测试和人工任务验收完成；发布后核验实际线上版本，再称“全站统一完成” |

批次有依赖顺序，不预先承诺未经盘点的完成天数。每批使用小范围、可回退的提交；最终统一之前不扩展到新产品功能。

## 5. 技术实施边界

- 建议新增 `ui/tokens.css`、`ui/components.css` 和小型主题/状态辅助模块；实施时根据批次 0 的清单确认最终目录。
- 将 `--paper`、`--bg`、`--surface`、`--panel` 等旧变量映射到公共语义，逐页迁移，避免一次覆盖所有 HTML。
- 公共样式使用命名空间，禁止用宽泛的 button/input/canvas 规则破坏工具内部布局或导出内容。
- 保留引擎计算、现有事件绑定、模型格式、图例尺度、用户数据、工具路由和必要特有控件。
- 不为 UI 统一重写整个技术栈，不批量删除旧工具；过渡期保留适配层，并列出后续清理条件。
- 首页打包 HTML 随源文件更新后重建，避免源码和上线资源不一致。

## 6. 验收清单

- 全部路由逐项检查，既检查单独打开，也检查实际存在的 iframe/跳转入口。
- 电脑端优先，至少覆盖 1440×900 与 1280×800；窄屏只做必要的可用性与溢出回归，专项移动端设计延后。
- 两种主题下检查正文对比度、禁用态、焦点、选中、错误、图例与字体加载失败；正文对比度目标 WCAG AA。
- 检查键盘焦点、Escape、模态框焦点返回、标签、快捷键与减弱动态效果。
- 验证真实任务：示例或真实模型导入、编辑、保存、重开、分析、比较、导出。单纯打开页面或截图相似不能作为任务通过。
- 按改动运行现有 smoke、shell、workflow、studio-tab、views、compare-2d、acoustics、interior 与 hero 相关测试；新增检查覆盖公共行为和真实回归，不测试实现细节。
- Mock、真实分析、失败、跳过与未执行分别记录；外部服务失败及既有应用缺陷不能用放宽断言来掩盖。
- 线上核验导航、模型交互、主题、核心任务与静态资源版本；网络受限时明确“已推送、未核验上线”。

## 7. 本轮交付边界

先完成公共设计系统和全站页面迁移，再做新功能和独立视觉升级。真实分析回传、正式账号、云存储、支付、报告引擎和新建模能力另立工作项。UI 阶段可以明确其状态和入口，但不宣称已补齐功能。

下一项可执行工作是批次 0 的路由/组件清单与批次 1 的公共样式参考，而非继续单独美化首页。
